# 现场配置与点表填写指南

本文面向现场工程师，说明如何把仓库里/旧系统里的 PLC 点表，翻译成这套系统需要的现场配置。

**核心原则：点表不是写死在代码里的。** 所有 PLC 字节布局、装载查表、锭位映射都存在中心数据库的"现场配置"里，可随时改、有版本号、可回滚。

---

## 1. 三类现场配置

| 配置 | 作用 | 谁需要 |
|---|---|---|
| PLC 点表 | 每个字段在 DB 块里的偏移、类型、长度 | 所有工位 |
| 装载位置查表 | 卷绕机锭位 + 落筒侧(A/B) → 料车位置 | 卷绕工位 |
| 外检锭位映射 | 打标头 + 段号 → 模块内锭位 | 外检工位 |

另外两类绑定不在"现场配置"里，而在各边端的 `edge.yaml`：

| 绑定 | 作用 | 谁需要 |
|---|---|---|
| `printers` | 打标机/标签机的 IP 与头号 | 外检、包装 |
| `palletizers` | 打包机 PLC ↔ 打包机号/厂编码 | 包装 |
| `warehouses` | 仓库 PLC ↔ 仓库编码 | 仓储 |

## 2. PLC 点表的三个层次

### 2.1 单块读取（最简单）

只关心字节变化，不解释语义。用于设备状态、心跳这类"看一眼就够"的数据。

```yaml
devices:
  - code: "plc-pack-01"
    host: "192.168.3.10"
    port: 102
    rack: 0
    slot: 1
    protocol: "s7"
    read_blocks:
      - { db: 1, start: 0, size: 50, tag: "status" }
```

### 2.2 轮询组（按字段解释）

知道每个字段是什么、多大、怎么解。用于落筒、打标、出入库这类**有业务语义**的数据。

```yaml
devices:
  - code: "palletizer-13"
    host: "192.168.5.16"
    port: 102
    rack: 0
    slot: 1
    protocol: "s7"
    poll_groups:
      - name: "pallet"
        interval_ms: 500
        db: 750
        start: 0
        length: 64
        points:
          - { name: "Palletizer.PalletComplete", type: "int16",   offset: 0 }
          - { name: "Palletizer.PalletAck",      type: "int16",   offset: 2, direction: "write" }
          - { name: "Palletizer.LotCode",        type: "string",  offset: 4,  length: 20 }
          - { name: "Palletizer.BobbinCount",    type: "int16",   offset: 32 }
```

**offset 是相对 `start` 的偏移**，不是 DB 内的绝对地址。绝对地址 = `start + offset`。

### 2.3 重复组（N 个机位）

一台 PLC 带 N 个相同的机位时，用 `repeat` 表达，不要手工写 N 份。

```yaml
poll_groups:
  - name: "winder_data"
    interval_ms: 500
    db: 555
    start: 0
    length: 4752
    repeat:
      count: 24          # 24 个机位
      stride: 198        # 每个机位占 198 字节
      sides:             # 双面：每机位左右各一份 UDT
        left:  { offset: 96 }
        right: { offset: 4 }
    points:
      - { name: "DatiBobine_DaWinder.Doff_No",    offset: 8,  type: "uint16" }
      - { name: "DatiBobine_DaWinder.CodeNumber", offset: 79, type: "string", length: 12 }
```

单面机位（不带左右两侧）时 `sides` 留空：

```yaml
    repeat:
      count: 120
      stride: 100
```

## 3. 字段类型对照

| type | 字节 | 说明 |
|---|---|---|
| `bool` | 1 | 配合 `bit`（0-7） |
| `int16` / `uint16` | 2 | 最常用（S7 的 INT/WORD） |
| `int32` / `uint32` | 4 | DINT/DWORD |
| `float32` | 4 | REAL |
| `float64` | 8 | LREAL |
| `string` | 必填 `length` | S7 STRING，遇 `0x00`/空格截断并裁两侧空白 |

**字节序固定为大端**（西门子 S7 默认）。如果读到明显离谱的数字（如 0x0102 读成 258 而不是 513），先查是不是 PLC 侧用了别的字节序。

## 4. 语义字段名是契约（重要）

打包机和仓库没有原始 UDT 源码（旧系统是 Electron 二进制），**无法逐字节还原布局**。所以这两类工位靠**字段名**驱动：

控制器按字段名后缀查找点位，不认偏移。只要名字对上，偏移随便改。

### 打包机必须提供的字段

| 字段名 | 类型 | 方向 | 必填 | 说明 |
|---|---|---|---|---|
| `Palletizer.PalletComplete` | int16 | read | ✅ | 本垛堆完 = 1 |
| `Palletizer.PalletAck` | int16 | write | ✅ | PC 回写"已处理" = 1 |
| `Palletizer.LotCode` | string | read | ✅ | 批号，缺了不出垛 |
| `Palletizer.BobbinCount` | int16 | read | ✅ | 锭数，缺了不出垛 |
| `Palletizer.GradeCode` | string | read | 可选 | 等级 |
| `Palletizer.Layers` | int16 | read | 可选 | 层数 |
| `Palletizer.TotalWeight` | float32 | read | 可选 | 总重 kg |
| `Palletizer.ProductDate` | string | read | 可选 | 生产日期，支持 `2025-04-16` / `250416` / `20250416` |

### 仓库必须提供的字段

| 字段名 | 类型 | 方向 | 必填 | 说明 |
|---|---|---|---|---|
| `Warehouse.SlotChange` | int16 | read | ✅ | 有库位变化 = 1 |
| `Warehouse.SlotAck` | int16 | write | ✅ | PC 回写"已处理" = 1 |
| `Warehouse.SlotAction` | int16 | read | ✅ | `1`=入库 `2`=出库 |
| `Warehouse.SlotRow` / `SlotCol` / `SlotLayer` | int16 | read | ✅ | 库位坐标，必须 > 0 |
| `Warehouse.OccupantType` | string | read | 入库必填 | `pallet` / `trolley` … |
| `Warehouse.OccupantID` | int32 | read | 可选 | 占用物 id |
| `Warehouse.LotCode` | string | read | 可选 | 批号（查不到则只按库位记账） |

### 打标机必须提供的字段（外检）

| 字段名 | 类型 | 说明 |
|---|---|---|
| `LaserPrinter.Start` | int16 数组 | PLC→PC 请求打印（第 i 头） |
| `LaserPrinter.Done` | int16 数组 | PC→PLC 打印完成 |
| `LaserPrinter.Step` | int16 | 当前段序 |
| `LaserPrinter.ModuleRead` | int16 | 模块数据已就绪 = 1 |
| `LaserPrinter.Alarm` | int16 数组 | 打标机报警 |
| `LaserPrinter.Id_Module` | int32 | 当前模块号 |

数组用 `repeat` 表达，`count` = 头数，`stride` = 单个元素字节数（int16 时为 2）。

## 5. 装载位置查表

```yaml
capacity: 24
patterns:
  - code: "dx"
    map:
      - { spindle_place: 1, a: 15, b: 16 }
      - { spindle_place: 2, a: 18, b: 17 }
```

- `spindle_place`：卷绕机上的锭位（1 起）
- `a` / `b`：落筒侧。同一车两个落筒，先落的记 A、后落的记 B
- 值：该锭在料车上的位置

`capacity` 是该模式能放下的最大位置数，用于校验 `a`/`b` 不越界。

**线路用哪个模式**由线路主数据的 `config.loading_pattern` 决定（例如 `{"loading_pattern":"dx"}`）。取不到模式时**不做位置计算**——不猜。

---

## 6. 外检锭位映射

```yaml
head_maps:
  - head_count: 6
    steps_per_head: 4
    capacity: 24
    entries:
      - { head: 1, step: 1, position: 1 }
      - { head: 1, step: 2, position: 2 }
```

- `head`：打标头编号（1 起，对应 PLC 的 `Start[i]`）
- `step`：段序
- `position`：模块内锭位

## 7. 怎么改配置

### 方式一：中心 Web 界面（推荐）

```
中心后台 → 现场配置 → 选边端 → 编辑 → 保存
```

保存即校验，不通过会**逐条列出所有问题**（不是遇第一个就停），一次改完。

### 方式二：命令行导入

```powershell
.\bin\siteimport.exe -server http://127.0.0.1:8101 -edge edge-winding-01 `
  -plc configs\devices\instances\spinning_sides.yaml `
  -loading configs\geometry\loading_sequences.yaml `
  -remark "卷绕线初始点表"
```

参数：

| 参数 | 说明 |
|---|---|
| `-edge` | 目标边端编码（必填，边端必须已注册） |
| `-plc` | 点表文件，多个用逗号分隔 |
| `-loading` | 装载位置查表 |
| `-heads` | 外检锭位映射 |
| `-dry-run` | 只校验不保存 |
| `-replace` | 整份覆盖（默认是**合并**：只覆盖本次给出的部分） |

**默认是合并模式**，这点很重要：只带 `-loading` 时不会把已验证的点表清空。

## 8. 改完必须人工确认

配置下发到边端后是**暂存**状态，不会自动生效。

```
边端页面 → 现场配置 → 看到「待应用：版本 N」→ 点「应用配置」
```

为什么必须人工确认：产线运行中切换点表等于换地址读数据，自动应用会让正在跑的产线突然读错数据。

未确认时，边端心跳上报的仍是**已生效**的版本号，中心会持续重发——直到有人点应用。

## 9. 常见问题

**Q：点表改了但不生效？**
A：检查三点。① 边端页面上是否点了"应用配置"；② 心跳的 `version` 字段是否变成新版本；③ 边端日志是否有 `site config staged`。

**Q：读到的数值明显不对（如重量是 1e-38）？**
A：多半是偏移错位或类型写错。用 `-dry-run` 校验只能查结构，**查不出偏移错**——偏移必须对着 PLC 程序或 UDT 定义核对。

**Q：字符串读到一堆乱码？**
A：`length` 设大了会把相邻字段吃进来。S7 的 STRING 实际是 `[最大长度][当前长度][数据...]`，如果 PLC 侧是标准 STRING，这里的 `length` 应填数据区长度。

**Q：日志刷 `plc connect failed`？**
A：点表里的 `host` 在这台机器上不可达。开发机上连不上现场 PLC 是正常的，但**不会产生任何业务数据**——不会污染库。

**Q：一车超过两个落筒，ERP 推不出去？**
A：ERP 侧 `trolleys` 表是"一车两落筒"的固定结构（`doffing_1_id` / `doffing_2_id`），超出部分无处安放。这是对方表结构限制，需要与 ERP 厂商确认。

## 10. 上线前核对清单

- [ ] 每台 PLC 的 `host` / `port` / `rack` / `slot` 与现场一致
- [ ] 每个 `poll_group` 的 `db` 号来自 PLC 程序或旧系统配置，不是猜的
- [ ] 每个字段的 `offset` 已对着 UDT 定义逐字节核对
- [ ] `repeat.stride` × `count` ≤ 块 `length`
- [ ] 双面机位的 `sides.left.offset` / `right.offset` 已确认哪边是左（标签左右容易反）
- [ ] 打包机/仓库的语义字段名全部齐全（缺必填项会拒绝出垛/出入库）
- [ ] `printers` 里的 IP 能 ping 通、端口能连上
- [ ] 配置导入后**在边端页面点了「应用配置」**
- [ ] 边端日志出现 `site config applied`，且无 `pull failed`
